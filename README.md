# SRP EVENT 🍂

Полноценный осенний ивент-портал Discord-сообщества SRP: **регистрация → личный профиль → 12 мини-игр → серверные COINS → общий рейтинг → финальный TOP 5**.

Интерфейс на русском языке. Авторская осенняя иллюстрация, локально подключённый Manrope, адаптивные игровые поля, управление с клавиатуры и сенсорного экрана, закреплённая навигация с балансом и местом в рейтинге. Никаких фиктивных участников или демонстрационных балансов.

## Быстрый запуск

Нужен **Node.js 22.13+** (используется встроенный `node:sqlite`).

```bash
npm ci
npm run dev
```

Откройте **http://localhost:3000**. Сервер слушает `0.0.0.0`; интерфейс и API работают на одном origin. Для Arena preview дополнительные URL или CORS-настройки не нужны.

```bash
npm run build       # TypeScript + production-сборка Vite
npm start           # production-сервер на том же порту
npm test            # 33 unit-теста движков, экономики и календаря
npm run test:e2e     # 6 комплексных браузерных сценариев, отдельная тестовая БД
```

Переменные окружения (см. `.env.example`):

| Переменная      | Значение по умолчанию | Назначение                              |
| --------------- | --------------------- | --------------------------------------- |
| `PORT`          | `3000`                | HTTP-порт                               |
| `DATABASE_PATH` | `.data/event.sqlite`  | Постоянная SQLite-база                  |
| `SRP_ADMIN_KEY` | случайно генерируется | Секретный ключ администрирования        |
| `NODE_ENV`      | development           | `production` для раздачи готовой сборки |

Переменные задаются в окружении хостинга/терминала. Если используется локальный `.env`, запускайте Node с `--env-file=.env` — файл не читается автоматически.

## Участие и вход

1. Новый посетитель видит **регистрацию**, а не главную страницу. Остальные разделы открываются после создания профиля (финальные результаты доступны всем после окончания).
2. Вводятся Discord Nickname, отдельный Discord Username и Discord ID из 17–20 цифр. Обязательно согласие с правилами. В форме есть инструкция, где найти ID.
3. Сервер создаёт уникальный код `SRP-XXX`, нулевой баланс и защищённую сессию. Сразу после регистрации открывается **личный профиль `/profile`**, а не главная. Все данные профиля берутся из ответа сервера на регистрацию, без ожидания дополнительной загрузки статистики; запоздавший гостевой ответ не отменяет вход.
4. Поверх профиля участник **один раз** получает секретный ключ восстановления. Нужно сохранить его, поставить отметку и нажать «Открыть профиль». Публичный SRP-код сам по себе не позволяет войти в чужой аккаунт.
5. Повторный вход, в том числе после завершения ивента, — `/login`, SRP-код + секретный ключ. Пароль от Discord нигде не запрашивается.

**Важно:** сейчас это самостоятельная регистрация с данными Discord, **не Discord OAuth**. Владение указанным аккаунтом автоматически не подтверждается. Для публичного призового ивента подключите Discord OAuth2 и проверку членства в сервере; перед выдачей наград подтвердите аккаунты победителей. Один и тот же username/Discord ID нельзя зарегистрировать дважды, однако это не заменяет проверку личности и защиту от мультиаккаунтов.

## Разделы

- `/` — регистрация / главная участника / итоги завершённого сезона.
- `/login` — восстановление входа с другого устройства.
- `/games` — 12 игр, поиск, категории, сортировка, личные рекорды и оставшиеся попытки.
- `/play/:id` — инструкция, настоящий игровой раунд, результат и награда.
- `/profile` — отдельные Discord-поля, копирование SRP-кода, баланс, место, игры, достижения, рекорды, история последних 100 начислений.
- `/leaderboard` — TOP 3, общий рейтинг с серверной пагинацией и поиском, выделение текущего участника. Обновляется каждые 15 секунд.
- `/rewards` — иерархия наград TOP 5 и победители после финализации.
- `/info` — правила, даты, экономика, FAQ, обработка данных.
- `/admin` — закрытая административная панель.

## Реальные мини-игры

Все 12 механик имеют отдельный серверный движок, а не статическую заглушку.

| Игра                    | Максимум | Основа награды                                                     |
| ----------------------- | -------: | ------------------------------------------------------------------ |
| Сапёр                   |      250 | Полное открытие 30 безопасных клеток; первый ход безопасен         |
| Тетрис                  |      200 | До 6 собранных линий, серверная гравитация и проверка столкновений |
| Змейка                  |      180 | До 18 собранных яблок                                              |
| Память                  |      150 | 8 пар; награда учитывает время и количество ходов                  |
| Реакция                 |      120 | Среднее серверное время реакции на 3 сигнала                       |
| Осенний полёт (Flappy)  |      100 | До 10 пройденных препятствий, серверная физика                     |
| Камень, ножницы, бумага |       80 | Победы в 5 случайных раундах                                       |
| 2048                    |      200 | Самая большая плитка; полный максимум за 2048                      |
| Лови тыкву              |       90 | До 18 попаданий за 30 секунд                                       |
| Осенний квиз            |      100 | 5 вопросов с серверной проверкой ответов                           |
| Цветовой ритм           |      150 | 7 уровней повторения последовательности                            |
| Секретное число         |       70 | Число 1–100, 7 попыток и серверные подсказки                       |

Большинство раундов ограничены 3 минутами. В реакционных играх учитывается сетевая задержка: сервер не доверяет клиентскому секундомеру.

### Ограничения экономики

- **5 раундов на игру в сутки**, включая проигранные и досрочно завершённые.
- **60 секунд перерыва** между раундами одной игры. Другие игры в это время доступны.
- Сутки сбрасываются в **00:00 UTC**.
- Можно иметь только один незавершённый раунд. Новый раунд в другой игре завершает предыдущий. Повторный запуск текущей игры продолжает существующий раунд.
- Первые заработанные коины: **+25 COINS** один раз.
- Награда в 3 разных играх за день: **+50 COINS** ежедневно.
- Первые 500 коинов, заработанных именно в играх: **+100 COINS** один раз.
- Достижения защищены уникальными ключами от повторного начисления.
- При равенстве балансов выше зарегистрировавшийся раньше; UUID — дополнительный стабильный критерий для одинаковых временных меток.

### Что проверяется сервером

Браузер отправляет только действие, идентификатор раунда и версию состояния. API **не принимает пользовательский итоговый счёт или сумму награды**.

Сервер проверяет владельца сессии, состояние игры, допустимые ходы, время, финализацию, доступность игры, cooldown и дневной лимит. Мины, скрытые карточки, ответы квиза, секретное число и время будущего сигнала не передаются в клиентском состоянии. Повторная отправка завершённого результата возвращает прежний результат без дополнительной выплаты.

Запись результата, изменение баланса, транзакция и бонусы выполняются в одной SQLite-транзакции. Есть ограничения БД, уникальный `session_id` результата, проверка версий при конкурирующих вкладках, rate limiting, HttpOnly cookie, хеширование токенов/ключей и проверка origin для изменяющих запросов. Серверные файлы, `.data`, ключи и базы закрыты также от файлового сервера Vite.

**Граница защиты:** серверная валидация устраняет поддельные балансы и произвольные результаты, но не доказывает, что допустимые действия совершает человек. CAPTCHA, выявление ботов, Discord OAuth и дополнительная проверка подозрительных рекордов нужны перед публичным конкурсом с ценными призами. Не заявляется абсолютная защита от автоматизации.

## Администрирование

**Пошаговая инструкция без технических знаний: [ADMIN_GUIDE.md](ADMIN_GUIDE.md)** — вход в панель, ключ, вкладки, COINS, пауза, выдача призов и резервные копии.

Если `SRP_ADMIN_KEY` не задан, при первом запуске генерируется криптографически случайный ключ в `.data/admin.key` (файл исключён из Git, права `0600`). Посмотреть его **локально на сервере**:

```bash
cat .data/admin.key
```

Откройте `/admin` и введите этот ключ. В production задайте отдельный длинный `SRP_ADMIN_KEY` через секреты хостинга. Не публикуйте ключ и не добавляйте его в репозиторий.

В панели доступны:

- поиск участников по никнейму, username, Discord ID или SRP-коду;
- Discord-данные, балансы, статус, персональная история и лучшие результаты;
- начисление/списание коинов с **обязательной причиной**, видимой участнику;
- блокировка/разблокировка и исключение из текущего рейтинга;
- результаты раундов и история начислений (последние 200 записей);
- включение/отключение игр, изменение названия, описания и максимальной награды;
- добавление новой вариации на одном из 12 существующих движков (новая механика требует нового кода движка);
- редактирование всех пяти наборов наград;
- название, даты в UTC, активность/пауза/запланированный старт;
- необратимая финализация с подтверждением `FINISH`;
- скачивание финального рейтинга в CSV;
- журнал административных изменений.

Пользовательская и административная сессии независимы. Ключ администратора не даёт вход в личный профиль конкретного участника.

## Начало и завершение сезона

**Ивент начинается 6 сентября 2026 в 00:00 UTC и завершается 20 сентября 2026 в 00:00 UTC.** Это ровно **14 суток, с 6 по 19 сентября включительно**. Дата окончания — исключающая граница: в 00:00 20 сентября начисления уже прекращаются. До начала регистрация и личный профиль доступны, игры заблокированы.

Даты отображаются и редактируются в UTC. При необходимости их можно изменить в `/admin` → «Настройки» до завершения сезона. Названия скинов и конкретные призы должны быть подтверждены администрацией; интерфейс не выдумывает их.

Одноразовая миграция заменяет прежний шаблон 1 сентября — 30 ноября на эти сроки, сохраняя участников, балансы, историю, награды и намеренную паузу. Она не перезаписывает другие даты, уже заданные администратором, и не меняет завершённые сезоны. Применение отмечается в `schema_migrations`, изменение календаря — в административном журнале. Удалять существующую базу не нужно.

Запланированный ивент активируется после наступления даты начала. Проверка срока выполняется при API-запросах и фоновым таймером каждые 30 секунд. Истечение даты окончания завершает ивент даже если он был на паузе. После перезапуска пропущенное окончание обрабатывается при ближайшей проверке.

При завершении:

1. Начисления и новые игровые раунды прекращаются, включая награды за незаконченные игры.
2. Сервер сохраняет **снимок всего итогового рейтинга**.
3. Главная становится страницей «SRP EVENT завершён» с TOP 5 и наградами.
4. Снимок больше не пересчитывается. Изменение балансов, статусов участников, наград и настроек завершённого сезона запрещено через API.
5. Повторная финализация безопасна и не создаёт другой результат.

Новый сезон — новая база/отдельный deployment. Не удаляйте данные завершённого сезона без архивирования.

## Архитектура и хранение

```text
src/
  main.tsx                 маршруты, защита регистрации, общая оболочка
  lib.tsx                  API, типы, сессия пользователя, polling, уведомления
  components/Artwork.tsx   авторские SVG-иллюстрации и иконки
  components/UI.tsx        навигация, карточки, доступные модальные окна
  pages/                   регистрация, портал, игры, администрирование
  styles.css               единая адаптивная осенняя дизайн-система
server/
  index.js                 same-origin API, авторизация, админка, HTTP/Vite
  db.js                    схема, одноразовые миграции, ledger, рейтинг
  engines.js               12 независимых серверных игровых движков
public/images/             оптимизированная локальная иллюстрация WebP
```

База содержит `users`, `games`, `game_sessions`, `game_results`, `coin_transactions`, `event_settings`, `auth_sessions`, `achievements`, `admin_audit`, `schema_migrations`. Включены WAL, внешние ключи, индексы и контроль неотрицательного баланса.

- `.data` и ключи не коммитятся.
- **Нужен постоянный диск**: ephemeral/serverless filesystem приведёт к потере базы после redeploy.
- Для резервной копии используйте SQLite backup API/`.backup`. Копирование только `.sqlite` во время записи без WAL небезопасно.
- Для небольшого временного ивента достаточно одного Node-процесса. Для нескольких экземпляров приложения переносите хранение/транзакции/rate limiting в общую инфраструктуру (например, PostgreSQL и Redis).
- Это React/Vite frontend, совместимый с обычным frontend-workflow Lovable, **но сервер не разворачивается как статический сайт**. При переносе только интерфейса в Lovable потребуется перенести API и хранение в серверные функции/БД, а не заменять их localStorage.

## Docker

```bash
docker build -t srp-event .
docker run -d --name srp-event \
  -p 3000:3000 \
  -v srp-event-data:/app/.data \
  -e SRP_ADMIN_KEY="ВАШ_ДЛИННЫЙ_СЛУЧАЙНЫЙ_КЛЮЧ" \
  srp-event
```

Для публичного доступа поставьте HTTPS reverse proxy перед приложением, настройте резервные копии и проверку Discord-аккаунтов, подтвердите сроки, награды и процесс выдачи призов. Административные сессии следует создавать только по HTTPS.

## Проверки

Unit-тесты используют отдельную in-memory базу. Проверяются все движки, скрытие секретного состояния, лимиты, атомарность ledger, уникальность SRP-кодов, недопустимые балансы, идемпотентность результатов и финализации, точный 14-дневный интервал, границы запуска/окончания и безопасная миграция календаря.

Браузерные тесты сначала собирают production-версию и используют отдельный сервер на `3001` и уникальную базу в `.data/tests/`, не затрагивая `.data/event.sqlite`. До запуска HTTP-сервера тестовый скрипт задаёт активный 14-дневный период относительно текущего времени, поэтому тесты работают и до старта, и после завершения настоящего сезона. Скрипт отказывается открывать существующие файлы или базы вне `.data/tests`. Если порт 3001 занят, тесты откажутся переиспользовать чужой сервер. Chromium поставляется dev-зависимостью. Linux-скрипт использует включённые NSS-библиотеки, поэтому не требует установки системного браузера. Сценарии проверяют:

- регистрацию с немедленным переходом в собственный профиль, сохранение сессии, вход с ключом, настоящий выигрыш, историю, cooldown, анти-replay и CSRF;
- все 12 игровых интерфейсов и реальные действия;
- мобильные страницы при ширине 390 px, меню и управление, отсутствие горизонтального скролла;
- полный личный профиль сразу после регистрации, даже при ошибке обновления статистики и запоздавшем гостевом ответе;
- регистрацию до старта, UTC-даты в другом часовом поясе браузера и запрет преждевременных начислений;
- админку, блокировки, корректировки, добавление/отключение игр, награды, паузу, финализацию и вход после завершения.

```bash
# Необязательно: сохранить визуальные снимки проверяемых экранов.
CAPTURE_SCREENSHOTS=1 npm run test:e2e
```

Изображение осеннего острова создано для этого проекта; в runtime нет сторонних запросов за картинками или шрифтами. Иконки Lucide и шрифт Manrope подключены через npm.
